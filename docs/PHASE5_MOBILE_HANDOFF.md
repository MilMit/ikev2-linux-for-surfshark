# Phase 5 Mobile Handoff

This branch contains the Android and iOS mobile adapter work for the Flutter migration.

## What is implemented

### Shared Flutter layer
- `MobileVpnCore` wraps the shared Rust-backed `VpnCore` on Android/iOS.
- Native status is polled and mapped into the shared connection state model.
- Mobile connection is currently WireGuard-first and intentionally rejects unsupported mobile protocols instead of silently falling back.
- Android VPN permission uses the system consent dialog and completes the pending Flutter call after the user responds.

### Android
- Native Flutter MethodChannel bridge.
- Foreground VPN service lifecycle.
- Official WireGuard Android `GoBackend` integration.
- WireGuard config parsing via the official WireGuard config API.
- Private profile location: app-private `filesDir/wireguard/<serverId>.conf`.
- APK and AAB debug artifacts are generated by GitHub Actions.

### iOS
- Native Flutter MethodChannel bridge.
- `NETunnelProviderManager` integration.
- Packet Tunnel extension with WireGuardKit.
- WireGuard configuration is passed to the PacketTunnel only when a tunnel is started; it is not persisted into NetworkExtension preferences.
- Shared profile location: app group `group.net.milmit.vpn/wireguard/<serverId>.conf`.
- Unsigned Runner.app and PacketTunnel.appex are generated separately for CI verification.

## Intentionally not considered verified without real devices/accounts

These require manual validation and are not claimed as production-verified by CI:

1. Real Surfshark WireGuard credentials and real server profiles.
2. Android VPN permission flow on at least one physical Android device.
3. Android always-on / lockdown behavior and OEM background restrictions.
4. iOS NetworkExtension entitlement approval, provisioning profiles, signing and TestFlight/App Store packaging.
5. Embedding the PacketTunnel extension in the final signed Runner archive.
6. DNS leak, IPv6 leak, reconnect, sleep/wake and network-change tests on real devices.
7. Play Store foreground-service policy review.

## Profile provisioning contract

Mobile native adapters expect a valid wg-quick profile named by server ID.

Android:

```text
<application files dir>/wireguard/<serverId>.conf
```

iOS:

```text
<App Group group.net.milmit.vpn>/wireguard/<serverId>.conf
```

A profile must contain at least `[Interface]` and `[Peer]`. Do not commit private keys, service credentials, generated WireGuard profiles, Apple signing material or provider secrets to this repository.

## Android local build

From `apps/flutter` on Linux/macOS/Windows with Flutter and Java 17 installed:

```bash
flutter pub get
flutter analyze --no-fatal-infos
flutter build apk --debug
flutter build appbundle --debug
```

Expected outputs:

```text
build/app/outputs/flutter-apk/app-debug.apk
build/app/outputs/bundle/debug/app-debug.aab
```

If the Android platform scaffold is missing, use the same scaffold/overlay procedure in `.github/workflows/mobile.yml`.

## iOS local build

Requires macOS, Xcode, Flutter, XcodeGen and Go.

First build the Flutter host app:

```bash
cd apps/flutter
flutter pub get
flutter build ios --debug --no-codesign
```

Then prepare and build the PacketTunnel extension using the exact pinned WireGuard Apple revision documented in `.github/workflows/mobile.yml` and `native/ios/project.yml`.

For an installable IPA, enable signing and use an Apple Developer team/provisioning profile with the NetworkExtension packet-tunnel entitlement and the configured app group.

## How to report a failed manual build

For Android send:
- `flutter doctor -v`
- `java -version`
- full output of `flutter build apk --debug -v` or the Gradle failure section
- Android version/device model if runtime failure

For iOS send:
- Xcode version
- macOS version
- full `xcodebuild` error section
- provisioning/entitlement error text if signing fails
- iOS version/device model if runtime failure

## Phase 5 completion rule

Code-complete means Android and iOS adapters, build pipelines, WireGuard engines, permission/tunnel lifecycle, diagnostics path and test artifacts are present. Production-ready is a later gate that additionally requires real provider profiles, physical-device leak/reconnect testing, store signing and release packaging.
